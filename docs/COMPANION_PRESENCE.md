# 实时陪伴：兴趣、安静后搭话与直接看画面

## 使用方式

在原设置抽屉中调整，不改数字人、聊天区或输入框的样式。

- **共同兴趣**：自由填写喜欢的话题、游戏或视频类型（最多 2000 字符）。当前 DSH 原生人格仍是身份来源；兴趣只是补充偏好，不改「蓝色大肥鱼」人设原文，也不从前端另造一份人格。
- **空闲时主动聊天**：DSH 插件模式中的独立开关，默认关闭。在语音连接存在、没有近期互动且没有正常生成/播放/说话/原生任务时，请 DSH 找一个自然的话头。不要求先开启屏幕陪玩、System One 或麦克风。模型也可选择不出声，不靠占位台词表示安静。
- **空闲聊天时可参考当前分享画面**：只在已有手动授权的共享上请求新帧；没有共享或取图失败时可以仅围绕近期话题/人格/兴趣交流，不假装看到桌面。
- **屏幕陪伴模式 → Jev 判断后陪伴**：保留原流程，判断时补入当前 DSH 人格及共同兴趣，让模型结合鲸鱼娘的性格判断哪里值得聊，而不是只找通用的重大事件。
- **屏幕陪伴模式 → DSH 直接看画面**：适合看视频、游戏等连续活动。经过原有采样、差分/静态刷新、忙碌、冷却和次数预算后，新画面直接进入原生 DSH preview，跳过 Jev 屏幕判断。DSH 自己决定聊不聊，非逐帧讲解。此模式仍只处理当下的一张新图，不上传视频流、不堆积截图。

直接模式**只绕过屏幕主动评论的 Jev 判断**。其他已开启的 System One 语音/情绪/用户提问意图判断仍独立运行；若不想做提问时的文本意图预判，可关闭「允许按需请求截图」，DSH 自己的 `view_current_screen` 工具仍可用。

### 主动陪看的说话方式

Jev 判断后的评论、DSH 直接看画面，以及空闲搭话中想聊新截图时，均引导角色像坐在用户旁边一样主动分享：直接切入对具体细节的看法、感受、判断、吐槽或联想，而不是先报幕、概述画面再加一句评价。细节只作必要的话头；可以自然抖机灵，也可以认真交流，不要求每次搞笑或反问。仍沿用当前人格、兴趣和近期交流，不修改人设原文。

这只是主动陪伴场景的提示词，不做输出过滤、关键词拦截或强制截句；不改触发阈值、任务或工具权限。用户明确要求解释或描述屏幕时，仍按原生普通提问回答，不套用主动评论风格。实际表达质量仍需真人场景验收，离线测试仅验证提示词投递及场景隔离。

## 默认值与范围

| 设置 | 默认 | 范围 |
|---|---:|---|
| `screen_companion_mode` | `systemone` | `systemone` / `direct` |
| `companion_interests` | 空 | 最多 2000 字符 |
| `idle_companion_enabled` | `false` | 布尔 |
| `idle_companion_after_s` | 120 秒 | 整数 30–3600 |
| `idle_companion_cooldown_s` | 180 秒 | 整数 30–3600 |
| `idle_companion_max_per_hour` | 6 | 整数 1–60 |
| `idle_companion_include_screen` | `true` | 布尔 |
| `idle_companion_max_reply_chars` | 64 | 整数 8–240，提示词建议，不截断句子 |

直接屏幕模式沿用屏幕采样、静态刷新、冷却、每小时判断/回复预算；「每小时最多 DSH 看画面次数」对应原来的判断预算，不等于实际说话次数。默认预算较保守，连续场景可自行调节，但更频繁的视觉模型调用会增加费用。启用配置不代表已经共享，设置保存不会自动启动采集。

已有保存值不自动改写。与其他语音配置一样，修改生效时退役旧连接，前端重新连接；屏幕授权仍需手动操作。MOSS-Live 不支持这些新增主动路径。

## 实现边界

- 语音环境提示说明先简短自然回应再开始等待操作，耗时/多步骤工作优先用子智能体，真实进展及时告知。简单任务可以直接做，不制造空洞进度、不拦截工具或程序强制委派。
- 人格来自原生 persona assembly 的人格槽位，既不给判断服务导出完整系统提示，也不导出工具规则、凭据或私有记忆。DSH 自己继续管理任务、工具、历史和记忆。
- 安静后的搭话使用本地单调时钟和轻量定时调度。普通互动、实际生成/播放会推迟下一次机会；等待期间不轮询付费模型。到期后仍有忙碌、单飞、共同冷却和请求限额检查，不取消用户已接纳的 DSH 工作。
- 图片复用当前会话的授权和新鲜快照协议；撤销/切换共享、断连和退出使未使用画面失效，不补发旧截图。浏览器被系统冻结、丢弃或电脑休眠时不能保证后台继续。
- 主动回复继续走原生 DSH preview、原 TTS/情绪/口型和播放器 ACK。成功且空的 idle/direct 回复表示模型选择安静；真实断流、协议损坏、TTS 错误仍保留诊断，不把错误伪装成安静。
- 新鲜度在取图、排队及提交前检查；提交后持续检查共享/用户输入/停止状态，但不会把几秒的 Jev 判断超时当作 DSH 首字超时，静默丢弃慢一点的模型回复，或在句子中途按 TTL 截断。模型请求自身仍有桥接超时。
- 已播报的主动评论经原生 context inbox 进入主会话。后续 preview 从 DSH 原生日志及 inbox 读取最新累计 ACK notice，按生成 ID 去重，避免重复念上一句；Jev 判断另有近期语音交流上下文。不会额外建立会话历史或记忆库。
- Jev 模式会将人格槽位及共同兴趣发送给已配置的判断服务；直接模式把新画面交给当前 DSH 视觉模型，可能比先做轻量判断更贵。不要在共同兴趣中填写密钥等敏感信息。
- 前端的「已请求」表示发起生成，不表示已经播放；设置中提供安静后搭话的等待/忙碌/冷却/限额状态，便于区别“没触发”和“模型保持安静”。
