# Dafeiyu protocol: Pipecat / RTVI

The production gateway is FastAPI on loopback port 8765 under `.venv-voice` (Python 3.12, Pipecat 1.15.0). Production static files are served from `web/dist`; Vite development uses 5173. Local speech is a separate process on 8766 under `.venv`.

The independently distributable DSH bundle contains an immutable `app/` payload and uses external `DAFEIYU_HOME` for environments, models, private settings, logs and ownership files. Package installation never starts services or downloads models; explicit CLI provisioning is required. `gatewayPort` / `speechPort` can isolate gateway/ASR ports (defaults 8765/8766); all servers remain loopback-only. See `DSH_RELEASE.md` for the npm bundle, dependency provisioning and resource-license boundaries.

## HTTP gateway

- Optional System One decision layer: `systemone_enabled` (defaultfalse), `systemone_provider` (`ark` fresh default / `tokentosea` legacy), `systemone_ark_model` (`doubao-seed-2-1-lite-260915` or matching `ep-...`), independent `systemone_ark_api_key` and legacy `systemone_api_key` secrets, `systemone_audio_enabled` (defaulttrue), `systemone_timeout_ms` (200–5000/default1200), `systemone_interrupt_threshold` (.5–.99/default.75), `systemone_confidence` (.5–.99/default.6). GET exposes only the respective `_key_set` markers; empty keys preserve them and `clear_systemone_ark_api_key` / `clear_systemone_api_key` explicitly clear them. Enable/switch requires the selected key and cannot combine with `moss_live`. Changes retire voice sessions. `POST /api/systemone/test` explicitly makes one paid fixed-text test using saved credentials and returns `{ok,provider,model,reason,elapsed_ms,behavior,verified_input}`; reads never probe it. No automatic cross-provider fallback. See [SYSTEMONE.md](SYSTEMONE.md).
- With this layer enabled, `voice.behavior` is an urgent server message `{type,epoch,source:'doubao-systemone'|'clef-omni'|'rules',model,reason,behavior}`. Behavior is a validated partial object `{emotion?,expression?,gesture?,energy?}`; energy is0–1. Semantic expression/gesture names are allowlisted, never model parameter IDs. The browser waits for the corresponding epoch's PCM consumption, preserves its source, applies current-epoch late results, and drops retired epochs. Manual settings retain precedence. Interrupted decisions are cancelled without delaying audio playback.

- `GET /api/health`: gateway liveness.
- `GET /api/voice/config`: actual engine/version, transport, rates, interruption/history policy. History uses conservative, playback-confirmed contiguous TTS-context prefixes.
- `GET /api/settings`: settings with `api_key_set` and `tts_api_key_set`, never either secret.
- `PUT /api/settings`: partial settings (`llm_base_url`, `llm_model`, `llm_api_key`, `system_prompt`, `speech_base_url`, `voice`, `temperature`). Empty key preserves the stored key. Save reconnects the voice session so services use new settings. Avatar/device preferences remain frontend-local.
- `owner_voice_only` is an optional Boolean setting, default false. Enabling it requires an available enrolled speech service. Voice sessions snapshot settings, so clients reconnect after toggling/deleting.
- `streaming_asr_preview` is an optional Boolean setting, default false. Stable meaningful online partial text may interrupt an existing reply; final SenseVoice text alone enters user history and the LLM. Owner filtering disables the preview path. Enabling also requires local speech `DAFEIYU_STREAM_ASR=1` and its pinned online model. Settings expose an experimental UI switch and reconnect without automatically acquiring a microphone.
- TTS selection: `tts_mode:'legacy'|'auto'|'cpu'|'gpu'|'api'` (default `legacy` for migration). An explicit saved mode overrides `DAFEIYU_VOICE_MODE`; legacy retains environment / `tts_engine` behavior. Configuration, launcher and runtime use `server/tts_policy.py`.
- Independent API settings: `tts_api_base_url` (default `https://api.openai.com/v1`), `tts_api_model` (`tts-1`), `tts_api_voice` (`alloy`), `tts_api_key`, `tts_api_speed` (0.25–4, default1), `tts_api_timeout` (5–180 seconds, default60). Remote API endpoints require HTTPS; loopback permits HTTP. Empty key preserves the stored key; `clear_tts_api_key:true` explicitly clears it. Clear plus a new nonempty key is rejected. Changing endpoint with a stored key requires a new key or explicit clear. Validation never returns input secrets. Saving routing, credentials or voice changes retires old voice sessions.
- `GET /api/status` adds independent `tts={mode,provider,device?,configured?,ready,detail,verification?}`. API status only checks configuration: `ready:false`, `verification:"not_probed"`; it never calls the synthesis endpoint. `speech.ready` describes ASR availability; independent `tts.ready` describes the selected model sidecar. GPU readiness requires actual `device:"cuda"`. Health probes run concurrently with bounded deadlines. See [TTS_MODES.md](TTS_MODES.md) for the PCM API contract, failure behavior and lifecycle ownership.
- Current model endpoints: `index_tts_url` (loopback8770), `moss_tts_url` (loopback8772), validated as HTTP(S) loopback. `optional.index_tts` and `optional.moss_tts` return configured/loaded/device/backend separately. `gpu_tts_model:index_tts|gpt_sovits` selects IndexTTS-2.5 native BF16 or GPT-SoVITS-v5-turbo FP16. The existing `index_tts_url` and `optional.index_tts` names are the backward-compatible GPU slot; only the selected model runs on 8770. Changing the model retires voice sessions and reconciles owned services. CPU is MOSS-TTS-Nano ONNX. The launcher never starts legacy CosyVoice/VITS.
- `conversation_mode: "pipeline"|"duplex"|"moss_live"` (default duplex). Duplex keeps input live during playback and permits interruption; pipeline feeds silence during actual playback. Both use the selected TTS and saved LLM configuration (DeepSeek by default), with `speech_to_speech_model:null`. MOSS-Live selects the actual cloud speech model and client delegation to that same LLM configuration; it replaces local ASR/TTS for voice sessions and supports audio only. The foreground model may answer directly; delegated tasks use DeepSeek. Configuration changes retire existing voice sessions.
- Legacy compatibility settings: `tts_engine:'local'|'cosyvoice'`, `cosyvoice_url` (default loopback8770). Sidecar URLs must be HTTP(S) loopback without credentials/query/fragment. Changing them closes the old voice session. `GET /api/status` includes independent `optional.index_tts` and `optional.moss_tts` health, distinguishing configured/requested device from actual loaded model state. Unreachable services are unavailable, not CPU fallback. Retired `tts_alignment` and `mfa_url` fields are removed by an idempotent Store migration; settings updates containing them return 422. MFA is not launched or probed.
- Owner policy changes (enable/disable, speech-service address, delete enrollment) close existing voice sockets with code4001 in the single-process deployment. A failed setting validation preserves current connections. Reconnection releases the old microphone and leaves capture disabled.
- `GET /api/voice/metrics/{session_id}`: content-free in-memory statistics. Most recent64 values per series, at most100 sessions, nearest-rank P50/P95 with sample count, reset on reconnect/process restart. STT/LLM/TTS TTFB/processing and start-to-client-ACK completion use distinct names. Counters include interruption, speaker rejection, rejected ACK and completed playback. These are not physical speaker measurements.
- `GET /api/voice/owner/status`: model/profile status; `enabled` reflects the user's filter setting, `service_enabled` reflects service capability.
- `POST /api/voice/owner/enroll`: multipart `files`, two to five 16k mono PCM16 WAV clips. Atomic template replacement only after all quality/consistency checks pass.
- `DELETE /api/voice/owner/enrollment`: deletes the profile and disables filtering. Clients reconnect without automatically opening the microphone.
- `GET /api/status`: bounded actual provider and speech readiness probes.
- `GET /api/sessions`, `POST /api/sessions`: list/create sessions.
- `GET /api/sessions/{id}/messages`: persisted role/content/interrupted history.
- `DELETE /api/sessions/{id}`: delete a session.
- `GET /api/memories`, `POST /api/memories {content}`, `DELETE /api/memories/{id}`: manual memories.

## WebSocket `/ws/voice?session_id=<created-id>`

Embedded panel activity is separate from ownership. DSH keyed-page detach or document hiding pauses only visual rendering and UI status polling. The retained App keeps its session, WebSocket, audio output, in-flight replies, already authorized mic/display capture and retries; returning does not reconnect, reauthorize, refetch settings or recreate Live2D. Manual stop, track revocation, actual disconnection, settings/session changes and real plugin disposal retain their cleanup semantics. Actual disposal destroys the retained root. This is in-page retention, not conversation persistence or memory, and cannot run through OS sleep, browser freeze/discard or host restart.

The explicit Start Screen Companion gesture requests output-context resume synchronously before requesting display permission, without awaiting or opening a microphone. An automatic reconnect never assumes autoplay permission. Panel visibility alone does not interrupt captions or audio; manual interruption still marks generated-but-not-necessarily-played text.

Use official `@pipecat-ai/client-js` 1.16.0 and `@pipecat-ai/websocket-transport` 1.8.2. Wire frames are binary Pipecat protobuf. Do not send retired JSON/base64-WAV/epoch messages to this endpoint.

Input is continuous PCM16 mono at 16000 Hz. Framework output is PCM16 mono at 24000 Hz, paced by its transport. Official serializers own protobuf and the RTVI envelope. Official client-ready/bot-ready completes connection. Opening the application initializes output without acquiring the microphone; the user explicitly enables recording.

Typed input uses `client.sendText(text, {run_immediately: true})`. Standard RTVI events carry transcripts, incremental bot LLM text, speaking transitions, interruptions and errors. Application additions:

- Client message `voice.stop`, empty data: calls `rtvi.interrupt_bot()` and responds `{stopped: true}`. Browser immediately invokes official media interruption too.
- Server message `{type: 'voice.duck', active: boolean}`: reduces configured gain to 25% during tentative overlapping user speech.
- Server message `{type: 'voice.speaker', accepted: false | null, reason: 'mismatch' | 'insufficient_speech' | 'verification_unavailable'}`: rejected/uncertain voice; no transcription, LLM turn or user history is produced. This message does not interrupt bot audio. Tentative VAD ducking still occurs and resets on VAD stop.
- Ordered server message `{type:'voice.playback.start', epoch, sample_rate:24000, text}` precedes an output TTS context; `text` comes from Pipecat's native spoken `AggregatedTextFrame` with the same context ID, rather than the whole LLM response. Missing matches produce an empty string. The browser queues a mapped expression for that epoch and applies it only on actual worklet consumption, once; boundary text is a compatibility fallback. `{type:'voice.playback.boundary', epoch, samples, sample_rate:24000}` follows flushed output. `samples` counts valid mono output PCM samples, including the final partial worklet quantum. This is context-level expression timing, not a precise phoneme/word event.
- Client message `voice.playback`, data `{epoch, consumed_samples, sample_rate:24000, completed:true}`: official player worklet reports actual valid samples consumed into the Web Audio graph. An exact context match is accepted once; stale, duplicate, invalid, failed or interrupted contexts cannot confirm. A reply has multiple native TTS contexts (`reuse_context_id_within_turn=False`); one context can contain a sentence or sentence group. This is not a sound-card/hearing measurement or word alignment. The transport serializes deserialization; worklet buffers retain their own epoch, flush the final tail, and keep running across underruns. Interruption clears media and resets its stream without disabling the default track for later replies.
- Mouth animation uses realtime wLipSync/MFCC analysis of the actual post-gain playback PCM, with explicit RMS fallback if the classifier is unavailable or stale. No `voice.playback.phonemes` message or trusted-hash timeline is produced/consumed. Worklet consumption gates activity; mute, stop, suspension and reconnect reset the driver. Pre-reset classifier frames and retired playback epochs cannot reopen the mouth. Shared compiled WASM is reused across reconnects; live worklets remain per AudioContext. This is approximate vowel animation, not measured phoneme alignment. See [REALTIME_LIPSYNC.md](REALTIME_LIPSYNC.md).

One active connection per session is supported in the single-process deployment. Overlap does not run a second pipeline. Rejected peers close outside the policy lock; close-handshake waits are bounded to two seconds, including policy changes, so an unresponsive peer cannot block other sessions. Disconnect cancels the worker and frees recording/playback resources. Reconnection does not silently reacquire the microphone.

The browser explicitly disables microphone and camera auto-initialization, initializes output once and waits for RTVI readiness with a 20-second deadline. Initialization/transport failures propagate immediately; timeout or cancellation disposes the attempt and ignores late readiness. The application owns retry/backoff and awaits the previous disconnect before creating its replacement; transport-level automatic socket reopening is disabled because it would skip the session handshake. Output interruption waits at most 500 ms for a running worklet, skips receipt waits on a suspended context and never fabricates playback confirmation. Media teardown closes the output context even if a cleanup callback fails and sends no playback acknowledgments after session shutdown starts.

`node scripts/check_voice_connection.cjs` validates real local RTVI readiness, duplicate-session rejection, other-session availability, reload/profile-switch reconnects, bounded worklet receipt waits and recovery after dropping bot-ready. It starts no microphone capture, LLM turn or TTS inference. `VOICE_CONNECTION_OUTPUT` selects an optional JSON report path; output resource counts are checked after reconnects.

Framework owns cancellation, queues and contexts. Chinese short acknowledgements overlapping bot speech map to native `UserBackchannelFrame`, preserving the reply. Final recognition uses local segmented ASR. Optional online previews require two stable results plus an explicit stop phrase or at least four meaningful characters; short acknowledgements and one-character noise do not start early turns. A per-utterance guard is checked twice downstream to drop late previews after VAD stop/new utterance/queue overflow. Preview text never enters user context. Empty early turns do not automatically regenerate an LLM reply. This is a heuristic with real-human false-interruption evaluation pending, not first-syllable semantic understanding.

Assistant history grows only through the contiguous sequence of exactly confirmed TTS contexts in a reply. Acknowledging a later context cannot skip an unconfirmed gap. Updates replace one assistant database record at its original turn position; empty reserved records are hidden and retired. After interruption, a previously confirmed prefix is preserved while incomplete contexts are excluded. Context-specific TTS failures invalidate that context rather than discarding earlier confirmed audio. Production LLM calls rebuild a bounded snapshot directly from the playback-confirmed Store history (latest 30 messages / 20,000 characters), preserving tools and tool choice. Repeated identical assistant text is never used to infer turn ownership; the shared framework context is also bounded. A late valid ACK can appear at its original position in a subsequent request. Pending server epochs are bounded at128 and completed entries retire promptly, including replies longer than128 contexts. This confirms complete audio segments, not the exact word at which the user interrupted. Hard false-interruption pause/resume remains unimplemented. Temporary VAD ducking preserves playback and restores gain. The old `/ws/chat` conversation protocol is retired.

Strictly validated empty `voice.stop` messages and dictionary `voice.playback` receipts bypass the ordinary RTVI message queue through an injected `RTVIProcessor` subclass. They still use official Pydantic models, client-message dispatch, native `interrupt_bot` and the same ledger validation. A slow `send-text` flush cannot hold Stop behind synthesis. Other RTVI messages use the framework queue. Browser pending text sends carry a local version; Stop/disconnect invalidates sends still awaiting audio resume, preventing an older text request from being sent after its cancellation.

After a manual stop the UI can offer an explicit continuation request. Clicking it sends a normal new user text turn that asks the LLM to continue with the confirmed history. It never restarts the cancelled worker or automatically sends a request; new text/voice input and reconnect clear the offer. Generated continuation can still repeat earlier words, and it is not seamless original-audio resume.

Generated assistant captions retained after a manual stop are explicitly labelled as generated text which may not have played completely. This display is separate from playback-confirmed database history. Typed input exposes Stop immediately while synthesis is pending; cancellation does not wait for the first audible PCM.

Client playback buffering is capped at240,000 mono samples (10 seconds at24kHz). Overflow stops playback, rejects completion for affected epochs and displays an error; it does not silently drop audio while confirming history. Worklet telemetry distinguishes queued/consumed/dropped samples, underruns and overflows. Receipt state has bounded pending and invalid sets; unavailable or invalid epochs fail closed. Disconnect releases both playback and the recorder's separate AudioContext and microphone tracks. A stalled connection times out after8 seconds, and the UI can retry without waiting indefinitely for an older disconnect.

## Local speech HTTP on 8766

- `GET /health`: ASR/TTS readiness, actual device and fallback detail.
- `POST /v1/audio/transcriptions`: multipart mono PCM16 WAV. Independent Silero activity detection prevents silent/noise inputs being transcribed; it does not impose the owner gate's two-second minimum. Response includes `text`, WAV format/duration and activity metadata. Offline SenseVoice token/word timestamps are explicitly unavailable, rather than invented. VAD intervals are speech activity, not phonemes. Extremely short utterances can still be missed.
- WebSocket `/v1/audio/stream`: optional online Zipformer CPU preview. Receives PCM16 mono16k, up to0.5s per frame and30s per segment, one active model client. Emits readiness and `{type:'preview',verified:false,text,tokens,timestamps,endpoint}`. Token timestamps are recognizer output and can be wrong. Online readiness separately reports enabled, files present, and actually loaded. It never authenticates a voice; the Pipecat adapter disables this path for owner-only sessions.
- With multipart `owner_only=true`, transcriptions require speaker verification before ASR. A non-true decision returns `{text: '', speaker: {accepted, reason, score, voiced_seconds}}`; missing profile/model fails closed with 503. Normal unfiltered requests remain available when filtering is off.
- `GET /v1/speaker/status`, `POST /v1/speaker/enroll` (`files`, two to five WAVs), `POST /v1/speaker/verify` (`file`), `DELETE /v1/speaker/enrollment`: local CPU speaker component. At least two seconds of VAD speech per sample; only embeddings are persisted. Similarity is not identity authentication; see AUDIO_ENGINEERING.md.
- `POST /v1/audio/speech`: JSON `{input, voice?, response_format: 'wav'}`, response mono PCM16 WAV.
- Optional `DAFEIYU_TTS_BACKEND=zipvoice` uses the maintained sherpa ONNX engine and explicit local reference WAV/text, with `speed` between0.5 and2.0. Default VITS remains available. CPU short-sentence measurements yielded one callback at completion; this is not proven incremental acoustic streaming or early native cancellation. The weight-license status is unresolved; see speech/README.md and VOICE_MODEL_DECISIONS_2026-11-06.json.
- `POST /v1/audio/speech/stream`: JSON `{input, voice?, response_format: 'pcm'}`. sherpa VITS native callback yields PCM16 little-endian mono with headers `X-Audio-Sample-Rate`, `X-Audio-Channels: 1`, `X-Audio-Format: pcm_s16le`. Unsupported engines return501 before streaming, allowing WAV fallback. Invalid requests, overload, runtime errors and midstream disconnect never trigger replay of full WAV. Once headers/PCM are sent, failure closes the stream rather than changing HTTP status.

`speech/pipecat_services.py` adapts these endpoints to SegmentedSTTService/TTSService. STT wraps raw 16k PCM segments as WAV once; TTS prefers callback PCM, falls back to decoding WAV only for404/501, and passes samples to the framework. Pipecat owns TTS contexts, resampling and output pacing. Each completed HTTP synthesis explicitly stops and removes its native audio context after text has been queued; the production per-context mode does not wait for the framework's default3-second inactivity flush between segments. The idle timeout exceeds the HTTP timeout so slower valid synthesis cannot retire a context before its first audio. Native callback output is incremental by segment, not a continuous text-input streaming model. Reused HTTP clients close at service cleanup. Native RTVI metrics report processor TTFB/TTFA/processing; they are not browser/speaker latency.

Inference uses bounded admission and serial model locks. Disconnected queued requests do not enter inference. Running native ASR/SAPI is not assumed preemptible; sherpa TTS checks cancellation at callbacks, and locks stay held until actual exit. Closing HTTP is not proof that device computation stopped.

Reuse and limitations: [VOICE_OPEN_SOURCE.md](VOICE_OPEN_SOURCE.md). Retired custom protocol measurements: [VOICE_AUDIT.md](VOICE_AUDIT.md).

## Local TTS sidecars and cloud speech

`GET /api/tts/voices` returns the saved MOSS ONNX CPU installation's public catalog: `{model:'MOSS-TTS-Nano',source:'service'|'installed_manifest',default_voice,voices:[{id,name,group}]}`. The sidecar's `GET /v1/audio/voices` reads its manifest without model loading. The gateway prefers that live service; only a stopped default managed loopback:8772 can fall back to the installed model manifest. An unreachable custom service, wrong model, malformed/oversize catalog or unsupported endpoint returns 503, never unrelated presets. Requests are bounded, redirects disabled, responses allowlisted. No audio codes, file paths or secrets are returned. Catalog availability does not mean synthesis readiness or evaluated voice quality. The existing `voice` setting selects a CPU preset; empty/`default` uses the first runtime preset. GPU reference voices, `tts_api_voice` and `moss_live_voice` remain independent.

Normal supervisor deployments default to `DAFEIYU_VOICE_MODE=auto`; bare gateways default to `manual` when absent. An explicit saved `tts_mode` takes precedence. `auto` selects the saved GPU model (IndexTTS-2.5 or GPT-SoVITS v5 turbo) on 8770 or MOSS-TTS-Nano 100M ONNX CPU on 8772 at a response boundary. `cpu` and `gpu` require the corresponding local model; `api` uses independent OpenAI-compatible speech credentials. Legacy CosyVoice/VITS sources remain for migration and tests but are not launched by current routing. An external sidecar is borrowed only after checking its model identity.

Both local model sidecars expose `GET /health` and `POST /v1/audio/speech`. The request contains text and voice, bounded to 2000 characters, and returns mono 24kHz little-endian PCM16. Errors before first audio return an HTTP error rather than a successful empty stream. Health checks do not load a model. `configured` means required files were found. Explicit GPU mode loads and performs real silent warmup on startup, then remains resident until the mode changes or the service stops. `ready` requires a live CUDA worker that completed warmup. Auto/CPU remain lazy; their idle workers unload after 180 seconds (GPT-SoVITS defaults to 900, configurable). Admission is serial; loading/warming conflicts return 409, unavailable workers return 503 without cold-loading inside an explicit GPU synthesis request. Inference is bounded to 180 seconds and 15MB PCM. Cancellation/disconnect terminates incomplete model work before releasing admission; explicit GPU is prepared again in the background. Failures retain an error until explicit retry.

Health and `/api/status` expose `state:unloaded|loading|warming|ready|error`, `preload` (policy), `resident` (live ready resident worker), `warmed_up` (actual inference completed), and `preparation_seconds`. No actual device or graph activation is claimed while loading. Warmup PCM is discarded without playback, history, LLM calls or API charges. `POST /api/tts/load` returns 202 for preparation of the saved explicit GPU route, validating service identity and preload policy first; other modes/mismatches return 409 and unavailable services return 503. The loopback sidecar's `POST /v1/model/load` is idempotent during preparation/ready, supports retry after failure, and returns 409 for lazy policy. The launcher derives `DAFEIYU_GPU_PRELOAD` from saved mode; this is not an independent user toggle.

GPU policy uses a bounded `nvidia-smi` free-memory query, with at least 6GiB as an admission policy, not a measured model requirement. Eligibility and `/api/status` route predictions do not prove successful inference. Index uses upstream BF16/KV cache with an explicitly configured reference WAV. CPU MOSS uses only ONNX CPUExecutionProvider and preset voice IDs. A selected GPU failure stops the current response; auto prioritizes CPU on the following response without replaying partially heard text. No automatic paid fallback is permitted. See [TTS_MODES.md](TTS_MODES.md).

### MOSS-Live bridge

`conversation_mode=moss_live` opens an authenticated server-side websocket to `wss://api.mosi.cn/v1/realtime?model=...`. Settings include independent `moss_live_api_key`, `moss_live_model` and optional `moss_live_voice`; secret reads expose only `moss_live_api_key_set`, and `clear_moss_live_api_key` explicitly removes it. Owner-only voice authentication cannot be combined with this mode. Configuration guards execute before local ASR probes. The launcher stops its own local TTS sidecars while preserving the saved TTS selection. The base ASR service remains available for status queries and switching back, but cloud voice sessions bypass it.

The bridge requires attach acknowledgment with `delegation=client`, successful session update and media acknowledgment for 16kHz mono PCM16 input / 24kHz mono PCM16 output with client playback. Binary input includes silence. `input.speech.started/stopped` becomes user speaking frames; transcript revisions update only this session's user message, including turn 0. Output binary audio is associated with the latest `response.audio.context`; ambiguous transcript ownership is rejected. The browser uses the same existing protobuf/RTVI transport.

The browser acknowledges actual audio consumption using existing `voice.playback.*` messages. The bridge sends upstream `playback.chunk.completed` only after consumption, and `playback.completed` only after audio.done and all chunk receipts. On upstream audio stop/interruption, playback is interrupted before snapshotting its last consumed samples. `voice.playback.stopped` is sent even if empty; the upstream stopped amount contains only the unfinished head chunk, excludes completed chunks, and is clamped to provider audio duration rather than transport silence padding. Unsolicited partial stops and out-of-order receipts are rejected before mutating the ledger. Assistant history requires final transcript and fully consumed audio.

Client delegations validate type/target, deduplicate IDs and honor cancellation. At most two tasks invoke the configured LLM, with zero request retries and a 60-second cap reduced by any shorter provider timeout. Results use `session.commentary.append` with delegation_id and bounded content. Websocket messages/queues, pending audio, replies and ID histories are bounded. Idempotent cleanup closes the upstream websocket and cancels delegation tasks even during pipeline cancellation. No health endpoint creates a paid MOSS session; key presence yields configured/not_probed, not ready. Real cloud/acoustic acceptance still requires a configured account and browser testing.

Forced alignment on 8771 has been retired from the application. No TTS route waits for complete-WAV alignment. Historical offline research remains outside the playback/runtime contract, and existing E-drive environments are not deleted automatically.

### Optional assistant initiative

Independent from user barge-in: `systemone_initiative_enabled` (default false) lets the existing System One provider classify whether the assistant should briefly contribute while the user is still talking. Effective only with `systemone_enabled`, `conversation_mode=duplex`, owner-only off, and a configured reply model. It does not start the microphone. `systemone_initiative_threshold` defaults .9 (.8–.99); `systemone_initiative_min_speech_ms` defaults3000 (1500–15000); `systemone_initiative_cooldown_s` defaults20 (10–120).

Additional bounded preferences: `systemone_initiative_wait_threshold` defaults .2 (0–.5), `systemone_initiative_max_reply_chars` defaults48 (8–80), `systemone_initiative_probe_interval_ms` defaults3000 (1500–10000), `systemone_initiative_max_probes` defaults3 (1–6). Times, lengths and counts require integers; probabilities require finite numbers. Changing any closes existing voice sessions; unchanged saves do not. GET merges defaults for older databases. Reading/saving preferences does not call cloud models.

The input processor makes at most the configured probe count per VAD utterance (default3), separated by the configured interval of newly received audio (default3 seconds). It reuses a valid recent online preview or obtains a <=4s snapshot from the installed local ASR, with a2s local preview budget. No final transcript is fabricated. One cloud request asks `speak_now:noul`, `must_wait:noul`, `intent:choice` (`wait|acknowledge|empathize|clarify|correct`). A contribution requires desire at least the configured threshold, must-wait at most the configured wait threshold (default .2) and a confident non-wait intent. Failure only means keep listening, never a rule-triggered interjection.

One accepted contribution per utterance and a connection-wide cooldown. No concurrent ordinary generation, pending playback or assistant speech. State is rechecked at the LLM gate, with a4s snapshot expiry. Stop/new speech/text/disconnect invalidate pending work. If the user stops before the speculative reply starts speaking, native interruption cancels it; the final transcript still takes the ordinary answer path. There is no idle autonomous conversation or audio muting for this feature.

DeepSeek receives the real, locally recognized partial text and a transient short-contribution instruction in an isolated context after the confirmed-history gate. This is not a stored user message or user-turn-end signal; the complete user transcript is preserved. The prompt and LLM output limiter use the same configured limit (default48 Unicode code points, including punctuation) and one sentence for the interjection; ordinary replies are unaffected. Assistant history remains playback-confirmed.

`voice.initiative` is a diagnostic server message: `{type:'voice.initiative',status:'accepted'|'waiting'|'unavailable',reason,source,model,desire?,intent?}`. `accepted` means a generation was requested, **not audio played**. The message contains no transcript/audio/key, and doesn't apply avatar behavior. `voice.behavior` remains playback-epoch-bound. Metrics add `systemone_initiative_probes|accepted|wait|unavailable|stale`. Probabilities/default thresholds and physical overlap behavior require real acoustic evaluation; local protocol fixtures don't establish them.

Client `voice.capture` uses exactly `{active:boolean}` and bypasses queued ordinary RTVI messages. Initiative starts capture-inactive, becomes eligible only after the browser successfully starts capture, and cancels pending decisions/uncompleted speculative contributions when capture is turned off. This is a lifecycle signal, not owner authentication. Normal response playback is not stopped by this signal. Disconnect always invalidates speculative work. Stale microphone-enable promises cannot re-enable capture after a newer off request.

## Optional screen companionship (DSH only)

### Presence extension (2026-11-16)

Settings add `screen_companion_mode:systemone|direct` (default `systemone`), `companion_interests` (string, max2000), and opt-in `idle_companion_enabled:false`, `idle_companion_after_s:120` (30–3600), `idle_companion_cooldown_s:180` (30–3600), `idle_companion_max_per_hour:6` (1–60), `idle_companion_include_screen:true`, `idle_companion_max_reply_chars:64` (8–240). Booleans and integers are strict. Saved configurations are not automatically enabled/rewritten. MOSS-Live does not support these proactive paths.

Direct screen mode bypasses only the screen `SystemOneClient.decide` call. It retains authorized stream, visual-capability, sampling/change/refresh, freshness, singleflight, busy, cooldown and budget gates. Preview metadata is `kind:'screen',screen_mode:'direct',images:[oneJPEG],companion_interests`; DSH chooses whether to speak. Other enabled System One tasks remain independent. Jev screen mode receives only the active native persona slots and configured interests as additional decision context.

Idle uses a local monotonic inactivity timer, independent of user-still-speaking initiative. It uses the same preview/audio/ACK pipeline, not a new Agent harness. Metadata: `kind:'idle',max_reply_chars:8..240,companion_interests,images?:[oneJPEG]`. A fresh optional snapshot is requested only from a live authorized stream; absent/timeout image permits text-only idle conversation, but revocation invalidates an already pending screenshot opportunity. Server `voice.idle` diagnostics have `status:waiting|accepted|unavailable` and a content-free reason. Accepted means generation requested, not audio played.

The private native `voice/context` response adds `busy:boolean` from native `agent.status` and reuses latest confirmed `dafeiyu-voice` notices from native log/inbox, deduplicated by generation, alongside public conversation. Only persona slots are exported, never the complete system prompt or private memory. Success with an empty preview is intentional silence **only** for idle/direct opportunities; ordinary empty responses and transport/provider errors retain their existing failure semantics. Actual playback notices remain the only source of confirmed heard speech.

Snapshot request `purpose:'idle'` uses the unchanged reply wire shape, like `purpose:'tool'`; no purpose is echoed by the client. No capture permission or media stream is acquired automatically. Detailed settings, behavior and testing boundaries: [COMPANION_PRESENCE.md](COMPANION_PRESENCE.md).

`screen_companion_style:quiet|balanced|lively` is strictly validated, saved and connection-retiring. Default `balanced` allows grounded everyday companionship on a static screen; `quiet` retains the conservative timely-value policy; `lively` seeks more opportunities without inventing content. All policies retain privacy/quiet/insufficient-evidence/repetition boundaries and the existing probability, busy, cooldown and spending gates. Proactive status/metrics/logs report the allowlisted effective `style`; a style is not a promise of speaking or calibrated probability.

During an explicitly authorized active share, server `voice.screen.sample` contains only `{type,stream_id:canonicalUUID}` at the configured sampling interval. The client samples only its matching live grant, without asking for permission, and sends the existing proactive frame format. Socket pulses and the local compatibility interval share a monotonic rate limiter, single-flight encoder and change/refresh filter; user-requested snapshots remain independent and expiry-guarded. Off/disconnect/disposal cancels the server sampling task, and stale pulses cannot restart capture. This avoids exclusive dependence on hidden-page timers, not browser suspension/discard guarantees.

`screen_companion_speak_threshold` is a strict finite number in .5–.99 (default .9); the lower bound was relaxed from .8 to .5 on 2026-11-15 in both the settings API and UI. Existing saved values are not migrated or lowered automatically. This does not change the separate speech-initiative threshold or any wait/privacy, busy, cooldown or budget gates. Saving retires the old voice session as before; a new authorized share uses the saved value.

Client RTVI messages use `voice.screen` with exactly `{active:boolean,stream_id:canonicalUUID}` and `voice.screen.frame` with exactly `{stream_id,seq:positiveInteger,width:1..960,height:1..540,mime_type:'image/jpeg',data:canonicalBase64}`. `data` has no data-URI prefix and decodes to at most 256KiB. Both are handled outside the ordinary RTVI request queue; image assessment remains single-flight, never queued, and stop invalidates outstanding work synchronously. No screenshot data is printed by the protobuf decoder. These controls still require the normal authenticated owner connection.

Server `voice.screen.status` contains `{type,status,reason,source,model,mode?,desire?,must_wait?,intent?,judgments?,replies?,frames?,rejected?}`. `accepted`/reply counts do not imply audio played. Transient timeout/network/circuit-open statuses keep the explicit share alive; authentication/configuration/unknown failures stop capture. User speech, stop, off and disconnect invalidate pending observations. DSH settings include read-only `screen_model_ready`; the frontend never posts this marker as configuration. Unknown/text-only model metadata refuses sharing before judgment charges, and native image admission rechecks model support before persistence. Proactive screenshots use native DSH attachments/isolated agents with no fake user turn in main history. The plugin adds no screen tool guard or follow-up-step veto; DSH owns tool permissions. Confirmed commentary enters the parent native inbox with scene/time, playback/ending state and the historical native screenshot reference. Reply-length settings are prompt guidance only; no punctuation/character clipping or fixed 256-token preview budget is applied. Static frames refresh after `screen_companion_refresh_ms` (default15000,5000–120000), including frames previously dropped while busy/cooling down; backend budget gates still apply. Microphone toggles do not revoke an independently authorized display stream; saving/session changes/disconnect do; hiding does not.

Proactive decision statuses additionally report `speak_threshold`, `wait_threshold`, `intent_confidence_threshold`, and, when available, `intent_confidence`, `intent_probability`, `non_wait_probability`. The first two compare against `desire`/`must_wait`; the third compares normalized total probability of all non-`wait` purposes, not one stylistic purpose's confidence. A modal `wait` always blocks. Uncertainty between `comment` and `cheer` must not veto otherwise strong evidence for speaking; user interruption/affect choices retain their existing exact-class confidence rules. No stored thresholds change. Logs include only allowlisted scalar probabilities/reasons, and `GET /api/voice/metrics/{session_id}` adds `screen:{sample_limit:32,decisions:[...]}` with bounded scalar-only proactive decisions; it contains no images, transcripts, keys, persistent memory or model outputs. The UI retains the current share's most recent proactive decision across busy/requested-screen updates, clearing it when sharing ends.

Optional user-requested screen input: `screen_request_enabled` (defaulttrue), `screen_request_threshold` (.75,.5–.99), `screen_request_timeout_ms` (2000,500–5000) are strict validated settings and retire old voice sessions when changed. With saved screen/System One configuration, an ordinary completed user turn makes at most one bounded text-only `look_at_screen:noul` decision. A positive result requests a fresh frame only when sharing is active: server `{type:'voice.screen.request',stream_id:canonicalUUID,request_id:canonicalUUID}`; priority client `voice.screen.snapshot` has exactly the existing screen-frame fields plus `request_id`. Only the currently waiting request/stream, newer positive sequence, valid JPEG and live input generation are accepted, once. Stop/disconnect/new input invalidates pending requests; screen-off resolves the normal question without an image. No capture permission is acquired automatically. Browser encoding, queued request and upload are expiry/generation-guarded; no stale image cache is used.

This path attaches the fresh picture to the real normal DSH user message exactly once (`kind:'normal',screen_state:'attached',images:[...]`), rather than a separate proactive comment; ordinary answer length applies. Tools, continuations and delegated work remain owned by DSH without an image-specific execution guard. No image/current permission yields explicit transient `screen_state` information instead of fake vision or permanent claims of inability. Normal images/messages follow native DSH retention, unlike isolated proactive observations; stopping sharing cannot recall already sent/persisted attachments. TTS and playback ACK retain their acoustic semantics. In native DSH mode, the complete DSH log, not a playback-confirmed projection, owns the chat transcript. See [SCREEN_COMPANION.md](SCREEN_COMPANION.md) for privacy, diagnostics and measured validation boundaries.

### Native model-requested screen tool

The plugin registers the native DSH tool `view_current_screen` with no arguments. It obtains a fresh image of the current browser-authorized display through `POST /api/voice/screen/snapshot`, authenticated by the existing private `X-Dafeiyu-Plugin-Token`. The body is exactly `{session_id:string}`; this session is resolved from the calling Agent, never a model-supplied argument. Native subagents may follow immutable `origin:'subagent'` / `parentSession` ancestry, with bounded traversal and cycle checks. Ordinary forks do not inherit another session's share.

The endpoint returns HTTP 200 `{available:false,reason}` for expected absence/timeout states, or `{available:true,image:{mime_type:'image/jpeg',data,width,height},captured_at,stream_id}`. The plugin validates the image and calling model's image capability, admits it into the native DSH attachment store, and returns a real tool image block plus structured attachment metadata (not base64 text). Normal owner, tool and attachment policies are unchanged.

Tool capture emits `{type:'voice.screen.request',stream_id,request_id,purpose:'tool'}`. The snapshot reply retains the exact existing wire shape; it does not echo `purpose`. Missing purpose or `purpose:'intent'` denotes the automatic intent path. A tool request does not depend on `systemone_enabled` or `screen_request_enabled`; proactive judging and automatic intent enrichment still do. Sharing requires the DSH visual model, enabled screen companion, active connected browser and explicit display grant; MOSS-Live remains unsupported. The tool never opens the display permission picker or microphone. It is read-only, not desktop control.

Tool and automatic snapshots are independently correlated and share the current stream/sequence and JPEG validation. New speech or an acoustic interruption does not cancel a DSH tool's pending capture; sharing changes, disconnect and retirement do. At most one tool capture waits per provider, using `screen_request_timeout_ms`; errors return an unavailable reason, never an old cached frame or speech-layer error. Native session attachment retention still applies.

## Native DSH conversation (2026-11-15)

In embedded mode the host supplies `nativeConversation.mount(element, sessionId, 'messages'|'composer')`. The existing application shell remains styled locally; the renderer is the complete DSH `conversation.content` Factory with native Session ownership, attachments, permissions and plugin rendering. Standalone mode retains its existing interface. A hidden panel does not disconnect the retained voice application. Only the editable native occurrence is unmounted; DSH retains its draft and shared Session binding.

The private host bridge accepts ordinary turns at `POST /v1/voice/turns` and promptly returns `{accepted:true,request_id}` after native queue admission. `GET /v1/voice/events?session_id=...` independently follows the Session's public assistant output, including additional model steps and later parent replies. Event IDs support bounded `Last-Event-ID` resumption, with `ready`, `reset` and heartbeat controls. `POST /v1/voice/state` carries `{session_id,connection_id,active,microphone}` as temporary environment information. Neither subscription closure nor `voice.stop` cancels an admitted Agent task. Native composer Stop remains an explicit DSH task cancellation control.

Detailed ownership, limits and test boundaries: [DSH_NATIVE_CONVERSATION.md](DSH_NATIVE_CONVERSATION.md).
