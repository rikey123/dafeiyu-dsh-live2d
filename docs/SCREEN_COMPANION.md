# 屏幕陪玩：大肥鱼原链路中的可选观察输入

兴趣设置、安静后主动搭话和 DSH 连续直接看画面模式，见 [实时陪伴说明](COMPANION_PRESENCE.md)。

## 使用

1. 在 DSH 选择支持图片输入的模型。设置接口通过原生模型元数据预检能力，未知或纯文本路由默认拒绝；实际提交图片前再次检查。
2. 在大肥鱼设置中启用“屏幕陪玩配置”并保存。选择 Jev 判断模式时需启用 System One 并配置判断服务；也可选择“DSH 直接看画面”，跳过屏幕主动评论的 Jev 判断。按文字意图自动附图仍需 System One，DSH 自主调用看屏幕工具不需要。
3. 点击原面板里的“开始屏幕陪玩”，在浏览器授权器中选择屏幕或窗口。不开麦也能使用；保存设置、进入页面和重连不会自动开始分享。
4. 分享时按钮显示停止入口和后台共享说明。切换 DSH 面板或浏览器标签后，已授权的屏幕/麦克风和进行中的回答继续，隐藏仅暂停角色/波形渲染。停止、切换会话、保存、断线或真正退出插件仍释放轨道，并取消尚未使用的判断。麦克风是独立授权，开关麦克风不会撤销已经授权的屏幕共享；不会因开麦自动共享或重新授权屏幕。可随时用浏览器的共享指示器停止；关闭浏览器、页面被冻结/丢弃或系统休眠不保证继续。
5. 分享后直接问“你能看到我当前屏幕吗”“帮我看看这个报错”。开启“允许按需请求截图”（默认开启）后，System One 判断本轮是否需要看当前画面；若有意图，浏览器重新截取一帧，交给 DSH **本次正常回答**，不是额外一句主动陪玩。未共享时会说明如何授权，不再笼统声称完全没有看屏幕能力。
6. DSH 还可自主调用原生工具 `view_current_screen`，例如理解“看这个”或确认操作后的画面。此工具与 System One 意图预判独立，即使关闭 System One 或“允许按需请求截图”也能使用；它仍只读取已经手动授权的当前共享。调用结果通过 DSH 原生图片附件送入模型，不是只有一段截图描述。是否调用由 DSH 决定，没有关键词硬路由。主会话及其原生委派子智能体可用，其他会话不能越过共享归属；不提供桌面点击能力。

默认采样间隔 2500ms、画面差分阈值 0.06、回复冷却 30s、每小时最多判断 60 次/回复 12 次、开口阈值 0.9、等待阈值 0.2、建议回复约 64 字、判断超时 3000ms。上述数值都可在设置里修改，有后端范围校验。回复字数只是提示词建议，不强制截句或截字；不再给评论固定 256 token 输出预算。MOSS-Live 不支持此项，单进程原生 DSH 语音链路才支持。限额在网关进程内跨会话/重连共用，重启进程会重置；这不是账单硬预算或持久计费系统。

新增“主动陪伴风格” `screen_companion_style`：安静 `quiet`（原保守策略）、自然 `balanced`（默认，允许基于确切画面的日常陪伴评论）、活跃 `lively`（更积极寻找交流机会）。普通/静态画面不再在自然/活跃风格里一概视为无价值。所有风格仍尊重用户安静要求、敏感隐私、证据不足、不重复、忙碌、冷却、限额和概率门槛；不是定时强制闲聊。修改后保存，生效风格会出现在最近判断的诊断中。

后台采样由有流 ID 的后端 WebSocket 脉冲辅助，不仅依赖可能被限速的前端 interval；两者共用单飞编码与限速，静态差分、刷新、后端预算均不绕过。脉冲只对已经由用户授权的当前流生效，不会重新打开采集或补发积压截图。

开口意愿阈值 `screen_companion_speak_threshold` 的可调范围为 **0.5–0.99**（2026-11-15 将最低值从 0.8 降为 0.5），前后端一致。默认仍为 0.9，升级不会改写已经保存的值。降低阈值可让中等开口意愿更容易通过，但不会绕过等待/隐私、意图、忙碌、冷却和次数上限；用户说话期间的主动接话仍是另一项独立配置。保存后需重新连接语音并手动共享屏幕，新值才用于新的观察链路。

新增可配置项：按需查看开关 `screen_request_enabled=true`、意图阈值 `screen_request_threshold=.75`、取得新截图的等待上限 `screen_request_timeout_ms=2000`、静态画面刷新间隔 `screen_companion_refresh_ms=15000`。按需查看是用户本轮请求，不受主动评论的冷却、回复限额或短句长度限制；依旧要求当前已授权共享及 DSH 图片输入能力。每个正常用户轮次最多新增一次有界、只含文字的意图判断；失败不重试、不猜测看到画面。

## 执行链路与边界

浏览器 `getDisplayMedia(video=true,audio=false)` → 32×18 本地差分 → ≤960×540、≤256KiB JPEG → 同源已认证语音 WebSocket → 后端重新解码、核验尺寸、去掉 EXIF、差分/限额/冷却/忙碌检查 → 豆包 System One `speak_now/must_wait/intent` → 高意愿且允许开口时 → DSH 原生独立临时 Agent 和原生图片附件 → 原有 TTS/情绪动作/口型/播放器。

用户按需路径：最终语音转写或文字问题 → System One `look_at_screen:noul`（只发送本轮文字和有限对话）→ 正意图且已共享 → 服务端发 `voice.screen.request` → 浏览器强制采集当前帧，`voice.screen.snapshot` 携带流 ID 和一次性请求 ID → 后端验证、去元数据 → 原生 DSH **正常会话**中原用户消息附一张图片 → 原有回答/TTS/播放确认。静态画面也会重新截取，旧图不缓存复用；迟到、重复、错流、停止后的图片不接受。没有图片时给正常会话明确的当前状态，不能凭历史截图假装仍能看实时桌面。

模型自主路径：DSH `view_current_screen` → 固定 loopback 鉴权端点 → 当前会话的已连接共享 → `voice.screen.request(purpose:tool)` → 浏览器新帧 → 原生 DSH 图片工具结果。截图等待与自动意图路径分别关联，不会因用户再次说话而取消工具；撤销共享、切换流及断连会退役等待截图。超时或未共享返回原因供 Agent 说明，不抛成语音故障、不自动重放旧图。两种路径共用可配置的截图超时，工具不受主动评论冷却/预算限制。

- 单判断并发、无截图队列；过期、停止后的判断和排队回复都二次检查，不能复活旧画面。
- 用户说话、生成/播放中或既有主动插话忙碌时不额外开启屏幕回复。它不会替代原有语音轮次、打断逻辑或 DeepSeek harness。
- 屏幕图片、工具、子智能体均使用 DSH 的原生能力与权限；本插件不额外禁用工具、不拒绝后续步骤，也不添加屏幕文字防护提示。主动评论用简短自然的提示词交代交流场景；按需查看只保留本来真实提出的问题一次。
- 确认播报后，将评论类型、时间、场景、真实已播内容、结束状态及历史截图引用通过原生 context inbox 衔接到主会话；不再只传半截字幕。未播出的内容不冒充已经听过，截图不冒充此刻的桌面。
- 非语音任务错误留给 DSH Agent 处理；语音层继续订阅并朗读其公开说明，不将任务受阻映射为语音故障。
- `accepted` 只是允许请求回复，不是已播放。只有真实播放器消费 PCM 的 ACK 才按原有投影写入已播放的助手前缀。
- 不增加自己的记忆系统。DSH 及独立 fish-memory 管理记忆和会话；原项目记忆接口在插件模式为 410。

## 隐私和诊断

主动观察的画面会发送给当前 System One 服务；符合条件时还会发送给当前 DSH 视觉模型供应商。按需意图判断只向 System One 发送文字，随后取得的新画面只作为本次 DSH 视觉回答的输入；主动观察仍可能独立评估其定时画面。浏览器不调用摄像头，不采集共享音频。网关不把截图写进本项目 Store，也不在诊断日志记录图片 base64；原生 DSH 的附件和会话日志可能持久保存，不能把 dispose 当成删除。新增附件二进制通过 junction 保存于 E 盘；原生 DSH 会话日志仍位于现有 DSH home。分享前关掉密码、聊天隐私、支付等敏感页面。

按需查看的图片会随原生正常会话按 DSH 策略留存，而不是只进入临时 Agent。停止共享会撤销尚未转交模型的画面，但不能撤回已经发送给供应商或已被原生会话留存的附件。

### 为什么可能一直没开口（2026-11-15 修复）

- 原来普通对话没有接入屏幕输入，所以用户问屏幕时仍只发文字。新增按需路径解决此问题。
- 原来先共享再开麦会静默停止共享；现在两种权限独立。最初切页方案仍会停止共享，现按用户明确要求改为后台持续，真正停止/失效才释放。
- 原来忙碌/冷却时被丢掉的一帧也会被前端记作“已送过”；若后续画面没变化，可能永远不再评估。现在静态场景按可配置刷新间隔重送，后端也允许到期复评，仍受主动判断预算约束。
- 原来 `must_wait` 和 `speak_now` 都把“画面普通”作为等待条件，产生重复抑制。现在前者只判断独立的安静/不宜打扰/隐私条件；没有降低用户已保存的概率阈值。模型仍可合理选择不评论。
- 判断超时曾因检查已经过期的 TTL 而丢失诊断，现在会报告超时。短暂网络/超时/熔断不再自动撤销共享；鉴权、模型能力或配置错误仍停止。

面板诊断显示收到帧、判断/回复请求次数以及 `busy`、`cooldown`、`budget`、`must_wait`、`wait_intent`、`low_confidence` 等独立原因。回复请求次数不等于已播放次数。网关日志新增无内容的 `screen status=... reason=...`，不含画面、用户问题或密钥；会话语音指标新增 `screen_*` 计数。配置开启不代表浏览器已授权；没有共享时不会后台偷偷采集。
